# V2 acquisition profiles (offline planning)

Run `.\.venv\Scripts\python.exe scripts\compare_v2_profiles.py` from the project root. The command only reads configuration and local V1 cache sizes; it makes no network requests, writes no data, and does not train.

`config/v2_profiles.yaml` compares June–September 2020–2025 at 00 UTC, Day 1–10, 0.25° on the existing 6–37°N, 68–98°E rectangle. Train is 2020–2023 (usable archive dates start in 2021), validation is 2024, and 2025 is held out as the final test period. V2 precipitation configuration now specifies interval accumulation; the V1 pipeline remains unchanged.

## Archive and scientific checks

The selected public 0.25° GFS AWS path returned 404 for sampled June and September 2020 `.idx` objects, while 2021–2025 samples returned 200. GEFS member and published mean/spread `.idx` objects returned 404 for the sampled 2020-06-01 date, 200 for 2020-09-30, and 200 for sampled 2021–2025 dates. These were metadata-only checks, not a complete daily inventory. The estimator excludes **all 2020 initializations** conservatively because the chosen GFS path was unavailable at both 2020 sample dates; it does not silently count them as available. A future archive source or reforecast product could restore 2020, but would need separate compatibility checks. Sources: [NOAA GFS open-data listing](https://registry.opendata.aws/noaa-gfs-bdp-pds/), [NOAA GEFS open-data listing](https://registry.opendata.aws/noaa-gefs/), [NCEP GEFS product inventory](https://www.nco.ncep.noaa.gov/pmb/products/gens/).

The GFS `.idx` samples at f024 and f240 in 2021–2025 identify APCP as **18–24-hour** and **234–240-hour** accumulations respectively. The preliminary V2 `0-{lead} day acc fcst` selector / `cumulative_to_daily` assumption was incompatible with these archives and has been replaced in V2. The profile estimates budget four 6-hour GFS APCP messages per day (40 per initialization), plus 13 instantaneous predictors at each of 10 daily leads (130), for **170 GFS messages per initialization**. V2 now checks each exact inventory interval, requires all four disjoint fields, and records the component forecast hours. At f006, both interval and cumulative APCP index entries describe 0–6 h; V2 deliberately selects the first interval entry. V1 is unaffected.

The GEFS published 0.25° `geavg` and `gespr` products contain 6-hour APCP ensemble mean and standard deviation fields (confirmed in 2021, 2022, and 2025 `.idx` samples). BALANCED budgets both products at all 40 six-hour steps, 80 messages per initialization. Four interval ensemble means may be summed to obtain the full-ensemble **daily mean**. Four interval standard deviations **must not** be summed or treated as the standard deviation of daily totals: interval covariance is unavailable. The implemented BALANCED contract retains explicitly named mean, maximum, and RMS **six-hour interval spread** features; it never calls them daily spread or invents daily quantiles/exceedance fractions. Those require member daily totals, so FULL retains all 31 members × 40 intervals. An 11-member subset would cost 440 GEFS messages per initialization and give only subset dispersion, not a full-ensemble replacement. [NCEP inventory](https://www.nco.ncep.noaa.gov/pmb/products/gens/).

ERA5 hourly precipitation spans the requested historical years according to [ECMWF CDS documentation](https://confluence.ecmwf.int/spaces/CKB/pages/181127817/The%2Bfamily%2Bof%2BERA5%2Bdatasets). The planner counts 25 required monthly requests/files for the **supported** 2021–2025 dates, including October verification hours after September initializations. Actual CDS job sizes/queue behavior and completeness remain unverified by this offline command.

## Estimation basis and interpretation

- `ESTIMATED_DOWNLOAD_GIB` is selected GFS/GEFS GRIB byte ranges plus 150 MiB per bounded ERA5 month. GFS message size is the median of existing local V1 cached GRIB messages when available, otherwise 0.807 MiB. GEFS APCP is budgeted at 0.45 MiB/message, above sampled `.idx` message-length observations of roughly 0.24–0.41 MiB. These are forecasts of network bytes, not quotes or guarantees.
- `TOTAL_REQUESTS` counts one index GET and one byte-range GET per message plus one CDS request per ERA5 month, excluding retries or CDS polling. It reflects the current per-message indexing approach; reuse of one GFS `.idx` file for multiple predictors could reduce HTTP operations, not GRIB bytes.
- `ESTIMATED_INTERMEDIATE_DISK_GIB` is raw download cache plus two uncompressed gridded working copies. Assumed bytes per row are 160 (LIGHT), 184 (BALANCED), and 240 (FULL). Actual Parquet/NetCDF compression and temporary peaks may differ.
- `GRID_ROWS` are 15,125 rectangle cells × 10 leads × initializations. They are **not** independent weather events. `THREE_DAY_BLOCKS` is a coarse diversity proxy; even those blocks need not be statistically independent during a persistent monsoon event.
- A post-extraction India land/state mask with a spatial-feature halo is provisionally assumed to retain 40% of rows. This would save roughly 60% of gridded intermediate table storage and later model computation, **not** any selective global GRIB-message download bytes, `.idx` requests, or the ERA5 bounding-box extraction. The exact fraction needs a complete validated India polygon/state boundary and chosen halo width; the existing limited central-state GeoJSON is insufficient. Compute precipitation gradients and other spatial context on the full grid first, then mask target/output cells.
- 2025 must not influence feature choices, thresholds, calibration, or model selection. Bust class balance must never be altered in validation/test. Primary evaluation is PR-AUC, ROC-AUC, precision, recall, F1, Brier score, reliability/calibration, and per-lead performance; raw accuracy is secondary.

## Recommendation

BALANCED every three days is the most storage-efficient starting point per coarse three-day weather block: 205 usable initialization dates (123 train / 41 validation / 41 untouched test), with published GEFS uncertainty information at about 38 GiB estimated download. If resources permit, BALANCED every two days gives 305 initializations (183 / 61 / 61) at about 55 GiB, but many extra dates fall in the same three-day weather blocks. The interval aggregation and BALANCED feature contract passed the bounded 2022-07-01 Day-1/Day-10 3×3-grid smoke test, including 48 exact ERA5 hourly endpoints. Full acquisition remains opt-in via `scripts/acquire_v2_balanced.py --full --confirm-full`; no bulk acquisition was started by this preparation.
